# Deployment in Stockholm

GPU Compare has its own deployment and URL. Use the local AWS CLI profile `portfolio` in `eu-north-1`. Run the commands from this repository. Use a shell without command tracing and keep Terraform state, plans, credentials and operator files private.

The public frontend and API share one CloudFront origin. In the demo, **Angebote laden** opens a session and checks provider availability. Check the API configuration for current rental availability and the results endpoint for completed public runs. [Open GPU Compare](https://dkvxgcdy40zyv.cloudfront.net) · [Rental configuration](https://dkvxgcdy40zyv.cloudfront.net/api/benchmarks/config) · [Public results](https://dkvxgcdy40zyv.cloudfront.net/api/benchmarks/results)

1. Run `uv run --frozen python scripts/prepare_aws_demo.py` for the read-only preflight. Confirm project identity in AWS Settings, active Free Plan, credits and room for another Express cluster and writer. Existing unrelated clusters count toward the quota. Review IAM restrictions before proceeding. [Free Plan limits](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-free-tier.html)
2. For the approved deployment, run the preparation again with `--apply --expected-account-id YOUR_VERIFIED_PROJECT_ID`. It creates or reuses the explicitly named, tagged GPU Compare cluster, configures 0–1 ACU, enables Data API and prepares the SQL and session secrets. Use the returned ARNs. The cluster and secrets are managed outside Terraform.
3. Set `AWS_PROFILE=portfolio` and `AWS_REGION=eu-north-1` in the shell. When the Terraform S3 backend needs environment credentials, use `eval "$(aws configure export-credentials --profile portfolio --format env)"` privately in that shell. Initialize, plan and apply `infra/bootstrap` using its own directory and state. Preserve that state. Its outputs are `state_bucket` and `repository_url`.
4. Sign Docker in with `aws ecr get-login-password | docker login --username AWS --password-stdin "$REGISTRY"`, using the registry from the repository URL. Build and push the Lambda image with `docker buildx build --platform linux/amd64 --provenance=false -f backend/Dockerfile -t "$REPOSITORY:$(git rev-parse HEAD)" --push .`. Look up the immutable image digest in ECR.
5. Copy the app tfvars example to ignored `infra/app/terraform.tfvars`, set the ECR digest URI and the SQL/session secret ARNs. Keep GPU admission disabled initially. Initialize the app backend with the new state bucket, key `gpu-compare/app.tfstate`, region `eu-north-1`, encryption and S3 locking. Review the plan for GPU Compare resources and apply. Invoke `gpu-compare-migrate` with a 210-second CLI read timeout. Check the invoke metadata for FunctionError and require a payload of `{"ok":true}`.
6. Build the frontend with npm ci and npm run build in frontend/. Sync the assets to the app stack's `web_bucket` with immutable caching, then upload index.html with no-cache. Invalidate / and /index.html on the distribution. The app's `demo_url` Terraform output is the public link. Verify /health, /api/benchmarks/config, session creation, the homepage on mobile and the empty comparison in a browser.
7. For later releases pin the new image and explicitly update Lambda code because Terraform ignores image changes after creation. Migrate and verify first, then update watchdog, worker and API. The optional manual GitHub deployment workflow implements this order and requires a successful push CI run. GitHub OIDC defaults to off.

## Activate real hardware

Store the Vast key in Secrets Manager as `gpu-compare/vast`. For private prompts also set `gpu-compare/gpu-operator` to an independent random password of at least 32 characters. Set only the ARNs in Terraform. Build the runner with `uv run python scripts/package_gpu_runner.py artifacts/private/runner.zip`. Upload to the dedicated reports bucket at `benchmarks/artifacts/<sha256>.zip` and configure the key and digest. Apply with admission still disabled. Check that the scheduler can invoke the watchdog, the watchdog heartbeat is fresh in S3, the provider inventory is understood, and there are no outstanding cleanup errors. Monitor the cleanup alarm and dead-letter queue.

With an approved Vast test budget, enable admission. Run the same Gemma suite on two affordable GPUs sequentially. Save both report IDs and verify the GPU names, runtime metadata, real counters, first-token times and VRAM samples. Confirm each rented instance disappears from the provider before the next run. Open both saved reports from a new public session. Keep real results distinct from test fixtures. If a create times out, inspect reconciliation and provider inventory before any subsequent rental. Disabling new admissions keeps cleanup running.
